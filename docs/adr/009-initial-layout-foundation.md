# ADR-009: начальный headless-фундамент tiling

Статус: **предложено**, требует ревью. Дата: 2026-11-08.
Это rationale первого среза, не замена решений и требований AGENTS.md.

## Контекст и границы

Репозиторий до первого среза не содержал Cargo workspace или реализации.
Tiling — фундамент продукта, а не фиксированная боковая панель терминала.
В доступном Linux-окружении нельзя подтвердить ConPTY, Windows IME/HiDPI.
Поэтому сначала реализуется проверяемая доменная модель; выбор Iced остаётся
гипотезой ADR-003, а Phase 0 — незавершённой.

## Предложение

Начать с трёх crates: core, application, executable. Не создавать пустые
адаптеры, публичные I/O traits и UI-заглушки до реальных границ интеграции.
Публичные API библиотек предварительные, persisted wire format ещё не существует.

- `LayoutNode` — рекурсивное бинарное дерево, не сетка с заданным числом ячеек.
- `Layout` скрывает изменяемое состояние, проверяет дерево и focus.
- UUID поступают извне: core не генерирует случайность и не обращается к ОС.
- `PaneId`, `ViewId`, `SessionId` различны. Swap перемещает целую пару pane/view,
  сохраняя focus на той же панели, а не в том же прямоугольнике.
- Команды создают кандидат, проверяют инварианты и только затем коммитятся.
- Ratio — целые basis points 1000..=9000: нет NaN и расхождений float equality.
  Некорректные значения отклоняются; UI позже сможет явно clamp pointer input.
- Горизонтальный split размещает детей сверху/снизу, вертикальный — слева/справа.
- Resize адресует непосредственный родительский split указанного pane;
  ratio всегда относится к первому ребёнку.
- После закрытия активной панели focus переходит к первой оставшейся панели
  в depth-first порядке. Последнюю панель закрыть нельзя.
- Лимиты: 256 панелей и 32 ребра от корня до листа. Это защитные бюджеты,
  не фиксированная сетка; изменение лимитов потребует тестов ресурсов.
- Undo хранит до 32 snapshot; focus-only и no-op не занимают историю.
  Ошибка не меняет ни layout, ни history.

## Lifecycle и ограничения

Дерево не содержит module kind или process handles. View registry с terminal
по умолчанию будет добавлен вместе с первой настоящей view, без редизайна дерева.
Layout-only undo может вернуть ID закрытой view, но **не восстанавливает процесс**.
До подключения PTY нужно определить reconciliation registry и подтверждение close;
нельзя напрямую трактовать undo как команду запуска старого shell.

В первом срезе нет геометрии, pixel minimum sizes, focus history, directional
navigation, move, persistence, окон/вкладок как агрегатов, shortcuts и
сериализуемых событий. Geometry/navigation и focus history добавлены следующим
срезом: см. ADR-010; ограничения первого среза здесь сохранены как контекст.
Эти требования остаются обязательными: см. roadmap. Ограничение ratio само
по себе не выполняет TILE-003 при маленьком окне.

## Проверка зависимостей

Проверены реальные metadata `cargo info` и Cargo.lock:

| Зависимость | Версия | Лицензия | MSRV | Назначение |
| --- | --- | --- | --- | --- |
| thiserror | 2.0.21 | MIT OR Apache-2.0 | 1.77 | Типизированные ошибки библиотек |
| uuid | 1.29.1 | Apache-2.0 OR MIT | 1.89 | Стабильные типизированные ID |
| proptest | 1.12.0 | MIT OR Apache-2.0 | 1.88 | Только тесты инвариантов |

uuid без default features в core; v4 включён только в executable. proptest
использует только std без fork/timeout, чтобы не добавлять Unix-only тестовый путь.
Это поддерживаемые upstream проекты; Windows/MSRV проверяются CI, а не обещаются
на основании Linux-сборки. Транзитивные зависимости фиксированы Cargo.lock.
Metadata включают разрешительные лицензии и Unicode-3.0 у unicode-ident;
полный advisory/license audit и комплект third-party notices перед выпуском
ещё обязательны. LICENSE и NOTICE этим срезом не меняются.

## Проверка решения

Unit/contract тесты ошибок, focus, swap/view identity, collapse и resize;
property-based команды против независимой модели порядка панелей;
bounded undo против модели snapshot. Обязательные fmt/clippy/test/check,
CI stable Linux/Windows и MSRV 1.89. Никаких заявлений о GUI/PTY производительности.
