# Выпуск Tervix для Linux

В GitHub откройте **Actions → Release → Run workflow**, выберите ветку
`main` и введите версию без префикса `v`, например `0.2.0`. Версия с
суффиксом, например `0.2.0-rc.1`, автоматически публикуется как prerelease.

Workflow ставит тег на SHA вершины `main` в момент запуска. Сборка использует
этот SHA, даже если за время ожидания runner в ветку поступили новые коммиты.
Номер версии записывается в Cargo.toml и Cargo.lock только в рабочей копии сборки.
Runner должен иметь метки `self-hosted`, `Linux`, `X64`, доступ к Docker и право
создавать теги и релизы с помощью `GITHUB_TOKEN`.

## Файлы релиза

| Файл | Установка |
| --- | --- |
| `tervix-v<VERSION>-linux-x86_64` | Выполните `chmod +x <файл>` и запустите бинарник. |
| `tervix-v<VERSION>-linux-x86_64.tar.gz` | Распакуйте архив и запустите `tervix` из него. |
| `tervix_<VERSION>_amd64.deb` | В Debian или совместимой Ubuntu выполните `sudo apt install ./<файл>.deb`. |
| `SHA256SUMS.txt` | Для скачанных файлов выполните `sha256sum --ignore-missing -c SHA256SUMS.txt`. |

Бинарник собирается в Debian 12 Bookworm для x86-64 с glibc. Архив подходит
для других дистрибутивов с совместимыми системными библиотеками. Для GUI
нужен графический адаптер с драйвером WGPU. Локальная PTY-сессия в этой версии
доступна только на Windows.

## Повтор после сбоя

Если тег уже создан, откройте упавший запуск и выберите **Re-run failed jobs**.
При совпадении SHA workflow использует существующий тег и дозагружает файлы
в черновик. Релиз становится публичным после загрузки всех файлов. Если тег
указывает на другой коммит или релиз уже опубликован, workflow останавливается.

## Проверки pull request

PR из веток этого репозитория запускают тесты Rust и Python в Linux-контейнере.
Для PR из форков сохраняется ограничение доступа к постоянному self-hosted runner.
