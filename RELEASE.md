# Выпуск Tervix для Windows и Linux

В GitHub откройте **Actions → Release → Run workflow**, выберите ветку
`main` и введите версию без префикса `v`, например `0.2.0`. Версия с
суффиксом, например `0.2.0-rc.1`, автоматически публикуется как prerelease.

Workflow ставит тег на SHA вершины `main` в момент запуска. Сборка использует
этот SHA, даже если за время ожидания runner в ветку поступили новые коммиты.
Номер версии записывается в Cargo.toml и Cargo.lock только в рабочей копии сборки.
Runner должен иметь метки `self-hosted`, `Linux`, `X64`, доступ к Docker и право
создавать теги и релизы с помощью `GITHUB_TOKEN`.

Runner хранит образы с зависимостями CI и релиза локально. При первом запуске
он использует имеющийся `rust:bookworm` или `rust:slim-bookworm`. При отсутствии
обоих скачивает slim-вариант с таймаутом пять минут. Повторные задания
используют подготовленный образ без pull и apt. Перед тестами или сборкой
workflow проверяет Rust, Cargo, компилятор C, Git, Python и инструменты своего
задания. Cargo сохраняет зависимости в каталоге кеша пользователя runner
(`~/.cache/tervix-actions/{test,release}` по умолчанию). Образы с установленными
инструментами и кеш Cargo сохраняются после окончания задания. Изменение
`scripts/runner.Dockerfile` обновляет ключ кеша. Для обновления базовой среды
вручную обновите локальный базовый образ и пересоберите образы заданий.

## Файлы релиза

| Файл | Установка |
| --- | --- |
| `tervix-v<VERSION>-windows-x64-Setup.exe` | Запустите мастер и выберите папку. По умолчанию это `%LOCALAPPDATA%\Programs\Tervix`. |
| `tervix-v<VERSION>-windows-x64.exe` | Запустите напрямую на Windows x64. |
| `tervix-v<VERSION>-linux-x86_64` | Выполните `chmod +x <файл>` и запустите бинарник. |
| `tervix-v<VERSION>-linux-x86_64.tar.gz` | Распакуйте архив и запустите `tervix` из него. |
| `tervix_<VERSION>_amd64.deb` | В Debian или совместимой Ubuntu выполните `sudo apt install ./<файл>.deb`. |
| `SHA256SUMS.txt` | Для скачанных файлов выполните `sha256sum --ignore-missing -c SHA256SUMS.txt`. |

Мастер устанавливает Tervix для текущего пользователя и добавляет ярлык в меню
«Пуск». Для удаления откройте «Параметры → Приложения → Установленные приложения».
Windows-бинарник собирается на Linux через MinGW-w64, мастер — через NSIS.
Оба файла выпускаются без подписи Authenticode.

На Windows мастер можно проверить в профиле без установленного Tervix:

```powershell
.\scripts\test_windows_installer.ps1 -Installer .\dist\tervix-v0.1.0-windows-x64-Setup.exe -Portable .\dist\tervix-v0.1.0-windows-x64.exe
```

Linux-бинарник собирается в Debian 12 Bookworm для x86-64 с glibc. Архив подходит
для других дистрибутивов с совместимыми системными библиотеками. Для GUI
нужен графический адаптер с драйвером WGPU. Локальная PTY-сессия в этой версии
доступна только на Windows.

## Повтор после сбоя

Если тег уже создан, откройте упавший запуск и выберите **Re-run failed jobs**.
При совпадении SHA workflow использует существующий тег и дозагружает файлы
в черновик. Релиз становится публичным после загрузки всех файлов. Если тег
указывает на другой коммит или релиз уже опубликован, workflow останавливается.

## Проверки pull request

PR из веток этого репозитория запускают тесты Rust и Python в Linux-контейнере.
Для PR из форков сохраняется ограничение доступа к постоянному self-hosted runner.
